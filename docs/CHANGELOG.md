# CHANGELOG

> 現狀總覽見 docs/ARCHITECTURE.md，本檔案只記錄歷史。

## 更新記錄

### 2026-10-26（掃描與多來源）
- 新增：多張圖片／資料夾模式可分次「加入…」多批來源，加「清空」與「重新掃描」按鈕；掃描時忽略已被刪除或改名的資料夾
- 調整：「共 N 張，預估約…」移到「開始」左邊，改 14pt 粗體，掃描中顯示「掃描中…」
  - 原因：原本張數只在清單下方與狀態列用小字顯示，不容易看到

### 2026-10-26（v1 獨立 GUI 工具）
- 新增：tkinter 介面，四種來源模式（單張／多張／資料夾／含子資料夾）、2／3／4 倍、預估與剩餘時間、停止與續跑、失敗清單
- 新增：VBS 無黑窗入口 + launcher.ps1（uv 建 venv）
- 新增：透明圖支援，RGB 走 Real-ESRGAN，Alpha 用 LANCZOS 放大後合回
  - 原因：原版轉 RGB 會失去透明背景；曾考慮放大前填 #00FF00 綠底方便去背，但邊緣會混綠，還要多一道去背，改成直接保留透明
- 重構：核心改自先前專案的 `scripts/upscale_cg.py`，拿掉綁定的 CSV 清單與固定輸出路徑，每張旁邊的 JSON 紀錄改為集中存 `cache/records.json`
- 新增：預估時間用依倍率的實測速度（每秒輸出像素：2 倍 90.5 萬、3 倍 198.7 萬、4 倍 247.6 萬），每批跑完以實測值覆寫到 `cache/settings.json`
  - 原因：倍率越高，每個輸出像素越便宜（運算量主要跟原圖像素有關），單一速度會讓 3／4 倍預估高估 2～3 倍。原本遊戲專案那次 9.72 秒是冷啟動，今天同尺寸只要 5.85 秒
- 修正：最終審查四項——遞迴掃描排除當機殘留的 `job-*` 暫存資料夾；同名不同副檔名改為後者標失敗；解除 Pillow 像素上限；連續引擎錯誤中止時狀態列明確說明
  - 原因：4096×3072 的 CG 放大 4 倍是 2 億像素，超過 Pillow 預設上限必定失敗（實測修正後 75 秒完成）；`cg01.jpg`／`cg01.png` 原本會互相覆蓋且永遠無法跳過。殘留 `job-*` 只排除不自動刪，避免在使用者圖片資料夾裡自動刪東西
- 修正：錯誤處理由「遇錯即停」改為「單張失敗跳過，連續 3 張引擎錯誤才停」
  - 原因：來源改為任意資料夾，一張壞檔不該卡住整批；連續引擎錯誤多半是顯卡／驅動問題，仍要停下以免整晚空轉
